# --------------------------------------------------------------------------- #
# Dependencies of the Vercel Python Function (`api/index.py`).
# --------------------------------------------------------------------------- #
# This file sits *next to the function it belongs to*, which is where Vercel's
# Python runtime looks for a function's dependency set.  It is deliberately not the
# repository-level `requirements.txt`: that one is the ~1.5 GB local stack (Streamlit
# + ydata-profiling + CatBoost + the plotting libraries) which README.md tells a
# developer to install and which Hugging Face Spaces / Streamlit Community Cloud
# install as well, while a Python function bundle is limited to 500 MB.
#
# `scripts/prepare_vercel_api_deps.py` runs as the project's *install command* and
# copies this file over the root `requirements.txt` inside the build container, so
# the function stays slim even if the runtime resolves the root file; vercel.json
# invokes it, and tests/test_vercel_deploy.py guards both the contents and the swap.
#
# The dashboard does not read this file - the browser build installs
# `deploy/vercel/requirements-pyodide.txt` instead.  Nothing else changes because
# `src/` imports every optional back-end defensively, so `available_model_names()`
# simply reports fewer models inside the function.

# Web layer.  `python-multipart` is the ASGI multipart parser that FastAPI needs
# for the `UploadFile` endpoints; it has no pinned upper bound.
