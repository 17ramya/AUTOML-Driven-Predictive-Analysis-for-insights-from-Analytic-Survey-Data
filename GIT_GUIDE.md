# Git & GitHub Guide for this repository

A practical, copy-paste guide to version-control the AutoML project, based on
exactly how this repository is laid out.  Every command is Windows PowerShell
(comments use `#`), but the same commands work in bash/macOS/Linux unless noted.

---

## 1. Why git at all?

Git records **snapshots** of the project so that you can:

* see what changed, when and why (`git log`, `git diff`),
* go back to any earlier state (`git restore`, `git revert`),
* collaborate on branches and merge through pull requests,
* publish a portfolio-ready repository on GitHub.

The mental model (four places your code can live):

```
 working tree  ──git add──▶  staging area  ──git commit──▶  local repository  ──git push──▶  remote (GitHub)
  (your files)               (index)                       (.git folder)                        (origin)
```

## 2. One-time setup

```powershell
git --version                     # is git installed?
git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global core.autocrlf true      # Windows only: keeps LF inside the repo
```

Check what is configured:

```powershell
git config --list --show-origin
```

Authenticate with GitHub (pick **one**):

```powershell
# a) HTTPS + credential manager (prompts once, then caches the token)
git config --global credential.helper manager

# b) SSH key (recommended for long-term use)
ssh-keygen -t ed25519 -C "you@example.com"
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub   # add this key to GitHub > Settings > SSH keys
ssh -T git@github.com
```

## 4. The everyday workflow

```powershell
cd "C:\Users\RAMYA S\OneDrive\Documents\github\AutoML-Project"

git status                     # 1. what changed?
git diff                       # 2. what exactly changed (unstaged)?
git add -A                     # 3. stage everything (or: git add src/app.py)
git status                     # 4. verify what is about to be committed
git commit -m "Add AutoML pipeline, CLI, dashboard and tests"   # 5. snapshot
git push                       # 6. publish to GitHub (origin/main)
```

Useful variants:

```powershell
git add src/preprocessing.py tests/test_preprocessing.py   # stage selected files
git add -p                                                 # stage hunk by hunk (review as you go)
git commit -am "Fix scaler round-trip at inference time"    # stage tracked modifications + commit
git commit --amend --no-edit                               # add staged files to the last commit
git push -u origin main                                    # first push, sets upstream
```

> **Rule of thumb:** one commit = one logical change, with a message in the
> imperative mood ("Add ...", "Fix ...", "Document ...").

## 5. What this project deliberately does *not* commit

`.gitignore` (already in the repo) keeps generated artefacts out of history:

| Ignored | Why |
| ------- | --- |
| `__pycache__/`, `*.py[cod]` | Python byte-code, machine specific |
| `.venv/`, `venv/` | virtual environments are rebuilt from `requirements.txt` |
| `data/source_data.csv` | generated by `main.py ingest` / `main.py run` |
| `models/*.pkl` | trained models, regenerate with `python main.py run` |
| `reports/*.html`, `reports/*.csv` | EDA/plot/report outputs |
| `catboost_info/` | CatBoost training logs |
| `diag*.py`, `*_tests.txt` | ad-hoc debug scripts used while developing |

The bundled **sample data** (`data/sample/**`, including the small images) *is*
committed on purpose — that is what makes the repository runnable out of the box.

Check what git would ignore:

```powershell
git status --ignored --short
git check-ignore -v models/automl_bundle.pkl
```

If a file was committed before you added the ignore rule, remove it from the
index (keeps your working copy):

```powershell
git rm --cached -r models reports
git commit -m "Stop tracking generated model and report artefacts"
```

## 6. Branches and pull requests

```powershell
git switch -c feature/gradient-boosting-tuning   # create + switch
git add -A; git commit -m "Tune Gradient Boosting on the sample dataset"

git switch main
git merge --no-ff feature/gradient-boosting-tuning
git push origin main
git branch -d feature/gradient-boosting-tuning    # delete the merged branch
```

Typical GitHub flow: push the branch, open a Pull Request, let the reviewer
comment, then *Squash and merge*.

```powershell
git push -u origin feature/gradient-boosting-tuning
```

## 7. Inspecting history

```powershell
git log --oneline --graph --decorate --all     # compact tree of all branches
git log -3 --stat                             # last 3 commits with file stats
git show HEAD                                 # full diff of the latest commit
git show HEAD~1:src/config.py                  # file as it was one commit ago
git diff main..feature/gradient-boosting-tuning --stat
git blame src/predict.py                      # who touched each line, when
git log --since="2 weeks ago" --author="Your Name"
```

Compare your working tree against the last commit *before* committing:

```powershell
git diff -- src/
git diff --staged            # what `git commit` would record right now
```

## 8. Undoing things (safely)

| Situation | Command |
| --------- | ------- |
| Discard changes in one file | `git restore src/predict.py` |
| Discard all unstaged changes | `git restore .` |
| Unstage a file (keep changes) | `git restore --staged src/predict.py` |
| Fix the last commit message | `git commit --amend -m "Better message"` |
| Undo the last commit, keep the changes staged | `git reset --soft HEAD~1` |
| Undo the last commit, keep the changes unstaged | `git reset HEAD~1` |
| Throw away the last commit **and** its changes | `git reset --hard HEAD~1` ⚠️ |
| Undo a public commit (safe, adds a new commit) | `git revert <sha>` |
| Temporarily park work in progress | `git stash push -m "wip"` / `git stash pop` |
| Restore a deleted file | `git restore --source=HEAD~1 -- path/to/file` |

⚠️ `reset --hard` and `push -f` rewrite history — avoid them on a shared branch.

## 9. Publishing this repository (first-time checklist)

```powershell
cd "C:\Users\RAMYA S\OneDrive\Documents\github\AutoML-Project"

# 1. Sanity check what will be committed
git status --short
git add -A

# 2. Commit the rebuilt project

# 3. Point the folder at your GitHub repository (skip if already set)

git remote set-url origin git@github.com:<user>/<repo>.git

#  For a brand-new empty GitHub repository instead:
#  git remote add origin git@github.com:<user>/<repo>.git

# 4. Publish
git push -u origin main
```

Verify the result:

```powershell
git log --oneline -3
git remote show origin          # branch tracking + remote branches
git ls-files | Measure-Object -Line    # how many files are tracked
```

## 10. Large files (the PDF and the deck)

The thesis PDF and the review `.pptx` are a few MB each — fine for plain git.
If you ever add files above GitHub's 100 MB limit (or want faster clones), use
Git LFS:

```powershell
git lfs install
git lfs track "*.pdf" "*.pptx" "*.pkl"
git add .gitattributes
git commit -m "Track binary artefacts with Git LFS"
```

Already-committed large binaries need rewriting history (`git lfs migrate
import --include="*.pdf"`), so it is simpler to decide **before** the first push.

## 11. Cheat sheet

```
git status -sb                 # short branch + status
git diff                       # unstaged changes
git add <path> | -A | -p       # stage files / everything / hunks
git commit -m "msg"            # snapshot
git pull --rebase              # integrate remote work on top of yours
git push                       # publish
git switch -c <branch>         # new branch
git merge <branch>             # integrate a branch
git log --oneline --graph --all
git restore <path>             # discard local edits
git stash / git stash pop      # park / restore WIP
```

## 12. Troubleshooting

| Symptom | Fix |
| ------- | --- |
| `fatal: not a git repository` | run the command inside the project folder (`cd` there first) |
| `Updates were rejected ... fetch first` | `git pull --rebase` then `git push` |
| `refusing to merge unrelated histories` | `git pull origin main --allow-unrelated-histories` (merge the two histories once) |
| `Support for password authentication was removed` | use a Personal Access Token or SSH (section 2) |
| `File ... is 120 MB; this exceeds GitHub's file size limit` | remove it from history (`git filter-repo`) or use Git LFS |
| Every file shows as modified after cloning | line endings: `git config core.autocrlf true` on Windows, `input` on Linux/macOS |
| Committed a secret (`.env`, token) | rotate the secret first, then `git rm --cached .env` and rewrite history |
| Committed a 40 MB `models/*.pkl` by accident | `git rm --cached models/*.pkl`, add it to `.gitignore`, commit |
| Wrong branch? | `git switch <correct-branch>`; move the commit with `git cherry-pick` if needed |
| Want to see everything git ignores | `git status --ignored` |

## 13. Recommended commit sequence for this rebuild

If you prefer several small commits over one big one:

```powershell
git add .gitignore requirements.txt src/ scripts/
git commit -m "Add library modules and deterministic sample-data generator"
git add tests/
git commit -m "Add 150+ unit tests incl. dashboard smoke tests"
git add main.py app.py
git commit -m "Add CLI (main.py) and Streamlit dashboard (app.py)"
git add README.md GIT_GUIDE.md docs/
git commit -m "Document architecture, usage and git workflow"
git add data/sample
git commit -m "Bundle reproducible sample datasets and images"
git push
```

Either way, finish by re-running the test suite on a clean checkout of what you
pushed:

```powershell
python -m unittest discover -s tests -t .
```
